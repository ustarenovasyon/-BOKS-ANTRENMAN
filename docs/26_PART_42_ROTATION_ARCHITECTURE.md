# PART 42 — Pivot / angle architecture

LOCKED architecture decision. Pivot and Stance Reset remain deferred canonical movements. Neither is added to the movement registry, curriculum or generated workouts in this release.

A future angle prescription must be a separate structured layer, not an attack punch and not a translation direction. Its contract must include pivot-foot role (lead/rear), stance-relative rotation direction (toward lead/rear side), commanded angle in degrees, before/after-combo phase and instruction-only semantics. A rotation model must explicitly define its coordinate frame before physical left/right or clockwise/counterclockwise is displayed. Translational Step In/Out/lateral movement IDs must never be reused to mean a pivot.

An instructional commanded angle is not an observed body angle. Without sensing there is no pivot accuracy, balance score or detection claim. Introducing pivot requires new canonical IDs, coverage validation, library version compatibility, curriculum prerequisites, budget treatment, audit validation, preview rendering and deterministic fixture coverage together. No partial production switch is permitted.

The complete current app therefore teaches the four already approved translation footwork movements, while preserving the requested Pivot/angle DEFER boundary.
